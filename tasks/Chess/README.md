# 百鬼棋局开发说明

## 一、新增阵容羁绊需要添加的内容

每套阵容使用一个独立的 Python 策略文件，文件名使用羁绊拼音。例如七角山使用 `qijiaoshan.py`。阵容专属信息应放在策略文件中，不应硬编码到 `script_task.py`。

### 1. 创建阵容策略文件

策略需要包含以下内容：

- `key`：阵容稳定标识，使用羁绊拼音。
- `display_name`：OASX 中显示的中文名称。
- `shikigami`：阵容式神配置。
  - 式神内部英文名。
  - 中文显示名。
  - 固定上阵位置。
  - 手牌识别图片文件名。
  - 商店识别图片文件名。
- `special_hand_cards`：阵容专属伴生卡或特殊手牌，可为空。
  - 中文显示名。
  - 图片文件名。
  - 通用操作类型。
  - 操作目标位置。
- `economy`：阵容经济策略。
  - 八阶以前的金币下限。
  - 八阶金币下限。
  - 九阶金币下限。

可参考 `qijiaoshan.py` 的结构：

```python
NEW_LINEUP = {
    'key': 'new_lineup',
    'display_name': '新羁绊',
    'shikigami': {
        'shikigami_name': {
            'display_name': '式神中文名',
            'position': 1,
            'hand_images': ('c_shikigami_name.png',),
            'shop_images': ('c_shikigami_name_m.png',),
        },
    },
    'special_hand_cards': {},
    'economy': {
        'pre_level_8_reserve': 44,
        'level_8_reserve': 25,
        'level_9_reserve': 0,
    },
}
```

### 2. 添加式神图片资源

所有阵容共用 `shikigami` 文件夹，图片不按阵容重复存放。推荐命名规则：

- `c_<name>.png`：手牌式神头像或手牌识别模板。
- `c_<name>_m.png`：商店式神头像模板。
- 其他特殊手牌应使用能明确对应内容的英文名。

同一式神可以被多套阵容共同引用。将新图片放入资源库后，仍需在阵容策略的 `hand_images` 或 `shop_images` 中登记；没有被当前阵容登记的式神不会参与该阵容的购买和上阵。

### 3. 注册阵容

在 `lineup.py` 中：

1. 导入新阵容策略对象。
2. 在 `LINEUP_REGISTRY` 中登记拼音键、中文显示名和策略对象。

```python
LINEUP_REGISTRY = {
    'new_lineup': {
        'display_name': '新羁绊',
        'strategy': NEW_LINEUP,
    },
}
```

`LineupBond` 会根据注册表生成。重新加载配置模型后，OASX 的“选择阵容羁绊”下拉框会自动显示新阵容的中文名称，脚本运行时会将中文选项解析为稳定的拼音键。

### 4. 新阵容应自行定义的内容

以下内容属于阵容策略：

- 阵容包含哪些式神。
- 式神固定站位。
- 手牌与商店图片资源。
- 阵容专属特殊卡。
- 不同等级的经济保留值。

刷新、购买、拖动、上下阵、星级识别、手牌清理和回目状态机属于通用功能，不应在新阵容文件中重复实现。若新阵容确实需要不同的运营动作，应先扩展通用策略接口，再由阵容配置选择对应行为。

## 二、主函数负责的内容

`script_task.py` 是百鬼棋局的通用执行器，不保存任何具体阵容的式神名单或固定经济数值。

### 1. 任务入口

`run()` 负责：

- 读取 OASX 中选择的阵容羁绊。
- 将中文选项解析为注册表中的拼音键。
- 加载对应阵容策略和图片规则。
- 读取执行次数与刷满鼬乐币选项。
- 读取“是否提前退出”和“剩余人数”；勾选且剩余人数大于 0 时，通过 `health_1-8` 中仍有数字的最大编号判断存活人数，连续两帧达到阈值时主动退出当前对局；填写 0 时不按人数退出。
- 导航到百鬼棋局大厅。
- 循环执行单局任务，直到满足结束条件。

### 2. 单局流程

`run_one_game()` 负责开始一局并进入回目循环。每局开始时会重置：

- 已确认的场上阵容。
- 脚本亲自上阵的位置。
- 御魂已满位置。
- 延期阵容整理任务。
- 延期经济任务及其子步骤。
- 脚本记录的商店开关状态。

结算时，主函数负责点击返回大厅、处理分享页面、安全点击以及排名页面返回，确认真正回到棋局大厅后才允许开始下一局。

### 3. 单回目状态机

`run_one_round()` 通过回目数和 `chess_mode` 协调以下阶段：

- `备`：优先选择 Buff，然后关闭商店、上式神、上御魂。
- `战`：先清理非阵容卡和纹章，再续跑未完成的经济任务。
- `鬼`：关闭商店并等待百鬼夜行自动结束。
- `待`：不执行操作，只等待状态变化。

第一套回合布局还会在“备”阶段空闲时读取 `now_time`。当剩余时间不超过 10 秒、当前没有延期阵容或经济任务且场上人数小于当前阶数时，每回目最多补做一次式神上阵；前三回合使用第二套布局时不读取该 OCR。

回目数字变化是强制边界。战后第二次“备”允许不存在；缺少该阶段时，主函数会保存阵容整理和经济任务，在后续合适阶段继续执行，不会将新回目的第一次“备”误判为旧回目阶段。

### 4. 通用上阵与下阵

主函数根据当前阵容策略提供的站位完成：

- 关闭商店后读取当前场上人数。
- 使用当前阶数作为最大上阵人数。
- 识别手牌式神并拖到策略指定位置。
- 比较手牌与场上星级，只用更高星卡替换。
- 记录脚本亲自上阵的位置。
- 回收系统可能自动放置在 9、10、11、12 号位的式神。
- 回收后立即重新上阵和装配御魂，避免系统自动上卡破坏阵型。

### 5. 通用商店与经济操作

主函数只加载当前阵容声明的商店头像，并负责：

- 扫描五个商店位置。
- 判断金币是否足够购买对应卡牌。
- 点击所有命中的阵容式神。
- 以目标头像从原商店格消失确认购买成功。
- 执行一次升级、一次刷新和一次购买组成的原子批次。
- 保存待升级、待刷新或待购买状态，以便跨回目续跑。
- 战斗中刷新图标被技能遮挡时，使用固定位置点击并通过金币变化确认结果。

金币下限由当前阵容策略提供，主函数只负责执行通用经济流程。

### 6. 通用手牌清理

非阵容卡清理和紧急腾位是两个不同流程：

- 非阵容卡、纹章可以直接出售，不受一星限制。
- 御魂、发现御魂和阵容特殊卡会被保护或优先处理。
- 手牌已满且非阵容卡已清空时，才启用紧急阵容卡出售。
- 紧急出售严格只允许一星阵容卡。
- 游戏会把不同种类的卡按价格排列，越靠右越便宜，因此从最右侧开始选择出售目标。
- 场上二星与手牌二星会共同参与冲三星保护；二星总数达到保护条件时，不出售该式神的一星卡。
- 场上已经三星时，取消该式神的冲三星保护。

### 7. 通用御魂和特殊卡操作

主函数负责识别攻击型和功能型御魂，并根据当前已确认上阵位置选择目标。阵容策略可以声明特殊手牌及目标位置，例如守护之印通过通用御魂拖放接口放到指定位置。阵容文件只声明“是什么、放哪里”，实际识别、长按和拖动由主函数完成。
