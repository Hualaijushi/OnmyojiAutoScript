### M4. `GeneralBattle` 基类退化区间

- **位置**：`tasks/Component/GeneralBattle/general_battle.py:36,156-157`
- **问题**：
  ```python
  PREPARE_CLICK_DELAY = 3.0
  PREPARE_CLICK_DELAY_RANGE = (PREPARE_CLICK_DELAY, PREPARE_CLICK_DELAY)
  SETTLEMENT_CLICK_INTERVAL_RANGE = (0.8, 0.8)
  ```
  写成 tuple range + 走 `_sample_interval` 说明**意图是随机**，但默认值让 `random_delay(x, x)` 在 `module/base/utils/random.py:102-103` 短路返回常量。除 `RealmRaid` 外的全部战斗任务：准备点击延迟恒 3.000s、结算点击间隔恒 0.800s 等距。
- **这是清单里影响面最大、同时最需要拍板的一条**，因为：
  - 改默认值 = 改变所有战斗任务的实际时序，属于变更「已确认的历史默认行为」；
  - `docs/AI_CONTEXT.md` §4.3 明确「不要重新加入 `reaction_delay` / `CLICK_REACTION_DELAY` / BaseTask 全局自动等待」，但未规定默认区间必须退化；
  - **无真机数据支撑任何具体新区间，本清单不推荐具体数值。**
- **可选处理**：
  - **方案 A（推荐本轮做）**：维持现状，只在类注释里写明「默认为固定值，子任务按需覆写（参见 `RealmRaid`）」，消除「以为已随机」的误读。纯注释，零行为变化。
  - **方案 B（单独立项）**：把默认改为非退化区间（数值由用户定），按 `RealmRaid` 的先例逐任务评估 + 真机验证。
- **风险**：A 零；B 中。
- **证据等级**：A（报告发现 03）

### M5. `RealmRaid` 退四分支的固定 4 次 `fire_again`

- **位置**：`tasks/RealmRaid/script_task.py:114-126`
- **问题**：`fire → run_general_battle → fire_again → run_general_battle → fire_again ...` 是无条件展开的固定序列，中途不按当前局面判断。若某次 `fire_again` 实际未进入战斗，后续 `run_general_battle` 会在非战斗页空转到 `battle_timeout`。
- **改法**：改为带次数上限的循环 + 每轮状态确认，写法可参考 `RyouToppa` 的 `_wait_for_attack_state` 风格。
- **风险**：中。触及 `RealmRaid` 核心流程。
- **验证**：**必须真机验证后再合。**
- **证据等级**：A（报告 §6）

## 明确不建议修改（防止后续顺手改）

以下都是源码里看着「很固定」，但已经过确认或有明确理由，改动收益不明、代价确定：

1. **截图 `Timer(0.1)` 与 `screenshot_interval_set` 限幅**（`module/device/screenshot.py:29,163-199`）—— 稳定性设计，改会影响全项目识别可靠性。
2. **`KekkaiUtilize.perform_swipe_action` 的 `swipe_adb` 与固定距离**（`tasks/KekkaiUtilize/script_task.py:1019-1037`）—— `docs/AI_CONTEXT.md` §4.11 查 `26715a72` 确认为引入时的有意选择，好友列表对滚动距离敏感，公共 `self.swipe` 从创建起即为注释状态。
3. **`tasks/Chess/runtime/press_and_drag.py` 两次固定 `wait(140)`** —— §4.10 明确为拖拽落点 settle 等待，属可靠性时序而非拟人化延迟，改会影响真机落点。
4. **点击全 ROI 均匀分布（不改中心偏置）**（`module/atom/click.py`、`image.py`、`ocr.py`）—— §4.1 的有意决定。
5. **不给 `RealmRaid.fire` / `GeneralBattle` 默认加 `confirm_delay`** —— §3.2 / §4.4。
6. **疲劳公式、概率参数、`rate_base` / `rate_max` / idle 时长** —— §4.9 明确「本轮之外不再调整」，且无真机采样数据。
7. **不要把 `np.random` → `SystemRandom` 记为反检测改进** —— §8.1 的归因修正，该替换不改变任何可观测分布。
