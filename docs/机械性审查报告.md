## 1. 总结

**是否存在明显固定行为：是。** 而且主要来自公共底层，不是个别任务。

- **最主要的固定行为集中在三个公共实现**：
  1. 截图节流 `module/device/screenshot.py:29` 的 `_screenshot_interval = Timer(0.1)`，配合 `screenshot.py:66-67` 的 `wait()+reset()`，让**整个项目所有视觉反应的时间下界是一个固定常量**，方差极小。
  2. minitouch 输入层 `module/device/method/minitouch.py:232` 的 `DEFAULT_DELAY = 0.05`，在 `minitouch.py:522` / `:593` 对**每一次点击 / 滑动 / 长按都追加一个固定 50ms 尾巴**。
  3. `module/base/timer.py` 的 `Timer` 全项目只用固定 `limit`，没有任何抖动；所有 timeout / interval / 卡死判定 / 战斗结算周期都是硬编码常量。
- **任务层 vs 公共底层**：公共底层问题更重。任务层的固定值（`time.sleep(0.5)` 一类）数量多但影响局部；公共底层的固定值影响面是「全项目」。
- **是否存在「看起来已随机化、实际调用链仍固定」的情况：存在，且不止一处**：
  - `GeneralBattle` 基类把「随机区间」写成了 `(3.0, 3.0)` 和 `(0.8, 0.8)` 两个**退化区间**（`general_battle.py:156-157`），`random_delay(x, x)` 直接短路返回 `x`（`random.py:102-103`）。除 `RealmRaid` 外的所有战斗任务，准备点击延迟恒为 3.000s、结算点击间隔恒为 0.800s。
  - `RyouToppa` 列表滑动精心抖动出的 `duration`（0.342~0.362s，±10ms）在 minitouch 控制路径上被 `Control.swipe` **直接丢弃**（`control.py:159-160` 只对 adb/uiautomator2 传 duration）。
  - minitouch pressure 随机化在当前 MuMu 环境是**空操作**（`max_pressure` 握手回退为 1，`minitouch.py:420-426`），`random_int(1, 1)` 恒为 1。此点交接文档 §8.1 已记录，本轮源码复核确认。
  - `np.random` → `SystemRandom` 迁移不改变任何可观测分布（同一 ROI 上是同一均匀分布），只提升可测试性。交接文档 §8.1 已记录，复核确认。

## 2. 高优先级发现

### 发现 01：截图节流器全局固定 `Timer(0.1)`，反应延迟下界零方差

- **文件**：`module/device/screenshot.py:29`、`:61-67`；限幅逻辑 `screenshot.py:163-199`
- **关键代码**：
  ```python
  _screenshot_interval = Timer(0.1)
  def screenshot(self):
      self._screenshot_interval.wait()
      self._screenshot_interval.reset()
  ```
  `screenshot_interval_set()`：普通场景 `limit_in(origin, 0.1, 0.3)`；`'combat'` 场景 `limit_in(origin, 0.3, 1.0)`；`scrcpy` 强制 `interval = 0.1`；nemu_ipc 下界 0.1。
- **调用链**：`BaseTask.screenshot` → `Device.screenshot` → `Screenshot.screenshot` → `_screenshot_interval.wait()`（`timer.py:149-156`，`time.sleep(diff)` 到固定 limit）
- **实际行为**：每次截图之间被强制拉到一个固定周期（默认 0.1s，战斗 0.3~1.0s 取配置固定值）。所有「出现即点击」的循环节奏因此有一个**几乎无方差的时间基线**。截图本身耗时的抖动是唯一的自然噪声源。
- **影响范围**：全部任务、全部识别循环。
- **证据等级**：A（`wait()` 直接 `sleep` 到固定 limit）
- **稳定性风险**：低——这本身是稳定化设计。
- **行为一致性 / 机械性**：高。交接文档 §8.3「第 3 层」已定性为「架构的自然产物」。

- **文件**：`module/device/method/minitouch.py:232`、`:281-285`、`:515-523`、`:583-594`

- **证据等级**：A
- **稳定性风险**：低。
- **行为一致性**：中~高（每次输入都有一段完全固定的收尾时长）。

## 12. 无法从源码确认的事项

以下需要源码之外的数据，**明确标注无法确认，不作推测**：

1. **实际单轮 / 单周期耗时的统计分布**（均值、方差、直方图）——需长时间运行日志。源码只能说明「哪些因素固定、哪些会变」。

4. **游戏服务端 / 客户端如何检测、检测阈值、网络侧特征**——不在源码内，**不推测**。本报告不涉及任何检测规避方案。

6. **慢设备 / 高负载下 `sleep(0.8~1.3)` 之类「猜测等待」是否足够**——需真机压测。
7. **`KekkaiUtilize` / `KekkaiActivation` 固定滚动距离（416 / 410px）是否会跳过或重复好友条目**——交接文档 §4.11 记录为「待真机验证」。
