# 上下文恢复与任务角色 V1.2

## 普通恢复

普通恢复首先取得当前仓库、Git、CURRENT 和本轮授权边界，随后按实际任务补充依据。辅助命令为 `toolkit/python.exe -B -X utf8 .agents/skills/oas-architect/scripts/oas_context.py status`，也可用现有只读工具取得相同事实。已取得的来源直接复用。

1. 识别用户本轮请求，复用已注入的项目规则。
2. 宿主要求查记忆时做一次相关的小范围检索，复用会话已有结果。项目辅助脚本专注当前仓库。
3. 核对实际根目录、worktree、分支、HEAD、暂存、未暂存、未跟踪文件、删除、重命名和冲突（各字段按维度独立计数，冲突/重命名/删除与暂存/未暂存不互斥；普通恢复遇到 returncode=0 的 stderr 警告会透传到 stderr 而不阻断恢复）。
4. 读取 CURRENT，恢复任务目标、批准范围、实施、验证、验收、保护事项和下一步。
5. 按任务模块和 CURRENT 的资料引用补充架构、有效 ADR、测试、计划及源码，记录已读范围与缺口。
6. 单独的恢复请求以报告收尾。用户明确要求继续开发时，接续已批准范围内的工作。

可报告基础状态已恢复、部分事项待补和真实阻塞。文件不可达或事实冲突只影响对应事项，已确认的信息继续交付。CURRENT 缺失时说明当前任务未知，并按用户明确的新需求继续分析。

## 预算提醒

普通恢复以 12000 Unicode 字符作为读取参考。达到参考值时说明原因、收缩可选历史检索，并继续补齐当前任务、授权和必要依据。预算预估不足、未知包装成本或超过参考值均采用提醒处理。

单次摘录可参考 6000 字符，长表按标题和实际行定位。出现乱码或截断时使用显式 UTF8、精确范围重试并保留已有成功内容。原始数量无法测量时标为估算，精确宿主读取量交会后审计。

普通路径无需 remaining、spent、正文 SHA 或 store/load 接收桥接。兼容旧入口时，预算参数同样只作提醒。必要的角色切换、授权与 WIP 保护按本文件和项目入口执行。

## 按需加载

| 层级 | 内容 | 触发 |
|---|---|---|
| L0 | 有效入口、Git、CURRENT 和必要摘要 | 新对话或任务接力 |
| L1 | 当前模块架构、有效决策、测试规范、计划和相关源码 | 设计、实施、诊断或审查需要 |
| L2 | 开发日志、归档、旧实现与历史证据 | 明确追溯原因、兼容性或旧行为 |

资料以当前任务为依据选择，保留真实标题和出处。六份核心 MD 按职责保存项目知识，按章节读取。旧决策检查替代状态，CURRENT 中的记录结合实际 Git 和源码核实。动态新增字段保留并提示含义，历史信息通过原始报告或副本追溯。

## 六种角色

每个新功能、修复或功能改动先确认需求并提交具体方案给用户审核；用户明确同意方案后才实施。已有同一方案的明确批准持续有效，范围变化先重新确认；只读调查不等于实施。

| 角色 | 请求示例 | 职责与交付 |
|---|---|---|
| 上下文协调者 | 恢复上下文、查看当前进度 | 当前任务、Git、授权、已知事实、缺口和下一步 |
| 需求分析与架构师 | 分析方案、设计功能 | 行为、范围、调用链、复用、不变量、取舍和验收条件 |
| 代码实施者 | 按方案实现、继续修复 | 批准范围内的增量、适用验证与实施报告 |
| 故障分析者 | 检查失败原因、核对日志 | 故障链、事实与推测、定位证据和修复建议 |
| 审查与验收者 | 审查修改、判断是否通过 | 对照需求、差异、实现与证据作结论 |
| 交接与文档维护者 | 准备任务包、保存检查点 | 执行者交接、CURRENT 和受影响文档同步 |

用户本轮请求优先，结合任务阶段选择角色，切换时简短说明职责。角色沿用用户批准范围。简单任务可由 Codex 实施，中型先明确方案，复杂任务分阶段获批。核心架构、L1 点击管线、双实例同步和跨模块重构须用户批准。

Codex 为技术负责人，负责开发结果的审查、必要最小测试及最终验收；开发统一由获授权的执行者承担，不绑定模型或客户端，Codex 可按授权接管。接管先核旧执行者停写、实际内容及基线。同一会话实施后的审查记录为自审，独立审查上下文注明来源和证据范围。详细交接见 [task-handoff](task-handoff.md)，正式审查见 [review-closeout](review-closeout.md)。

## 权限与保护

恢复和角色切换沿用现有授权，单独的只读请求以报告收尾。Git 写入、设备与服务启动遵循用户明确批准。全部预存 WIP 受保护，写前按批准范围建立可比较的开始内容，区分 HEAD→开始和开始→当前增量，来源不明的变化保留并报告。

CURRENT 由一个指定 Codex 维护，写前核 revision 与内容，变化先合并。任务、批准、阶段、验证、阻塞、接管和结束时更新，分别记录生命周期、实施、验证和验收。跨环境携带必要合同、基线和依赖。六份文档按事实变化同步。

## 严格验收入口

用户明确要求审查或验收时，先确定对象、版本、批准标准和证据范围，再按 [review-closeout](review-closeout.md) 工作。代码验收核需求、实现和适用验证。读取预算、完整快照及正文接收协议在对应的专项验收中启用。
